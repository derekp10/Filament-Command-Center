1. **How many lines when a finished print's file reads differently from the slicer (65.2).**
   - What: FCC walks a finished print's file and compares each head's total with the slicer's own figure. Past 2% (and 0.1 g) it writes a warning. The charge never changes.
   - Where: the Activity Log and hub.log.
   - Real example: the INDX's job 1135 (2026-11-03), read with the walker from before the `;EXCLUDE_E` hotfix, was off on all four heads: RCOI-1 7.50 g against the slicer's 3.23 g (+132%), RCOI-2 4.63 against 1.90, RCOI-3 1.07 against 0.35, RCOI-4 1.14 against 0.41.
   - Options: (a) one line per print, naming every head; (b) one line per head, as a cancel does today (four lines for job 1135).
   - Recommendation: (a). The charge isn't affected, and what's wrong is one file.
   - If he doesn't answer: (a).
2. **Does a Net reading count as a weighing? (65.3)**
   - What: each weigh save will say whether it was a weighing ("⚖️ Weighed … FCC expected …") or a hand edit ("✏️ Weight edited by hand"), so the later steps learn only from real weighings.
   - Where: Quick Weigh (the ⚖️ on a spool card) and the Bulk Weigh-Out list, with their modes Gross, Net, Additive and Set Used.
   - Real example: the weigh-out list opens in Net, and he types 425 for #57. Did that come off the scale (the empty spool taken off in his head, or with the scale's TARE), or from somewhere else?
   - Options: (a) Gross and Net are weighings, Additive and Set Used are hand edits; (b) only Gross is a weighing; (c) Net gets a "from the scale" tick.
   - Recommendation: (a), with Net's line saying "empty spool taken off by hand", so those can be left out later.
   - If he doesn't answer: (a). His ⏸️ PENDING DEREK "weigh the spool add-ons once" item asks the same thing; nothing waits on it.
3. **How much log to keep (65.4).**
   - What: FCC's own log file (every Activity Log line, plus errors) keeps 6 files of 1 MB and deletes the oldest.
   - Where: `InventoryHub\inventory-hub\hub.log` on the NAS.
   - Real example: from 2026-02-16 to 02-19 one repeated line filled four of the six files and pushed out everything logged before 02-16. Since April the log has grown about 66 KB a month.
   - Options: (a) 20 files of 5 MB (100 MB): today's rate never fills it, and a February-size burst would take about 38 days; (b) one file per day, kept N days (it needs test changes, and Python 3.9's cleanup of dated files has known bugs); (c) leave it at 6 MB.
   - Recommendation: (a).
   - If he doesn't answer: (a).

**A prod fact for the orchestrator, not a decision: may FCC's TrueNAS container ping? (65.1 (3))** The image is `python:3.9-slim` with no `ping` program, so FCC would ping from Python. An unprivileged ICMP socket works when the container's `net.ipv4.ping_group_range` covers the process's group (Docker sets that range wide by default, since 20.10). A raw ICMP socket needs the `NET_RAW` capability (in Docker's default set, but an app's settings can drop it). Prod's app settings live in TrueNAS, not in the repo. Read-only checks in a TrueNAS shell (Derek, or Claude with his OK; nothing here writes):
1. `sudo docker ps --format '{{.Names}}  {{.Image}}' | grep -i inventory`: the FCC container's name (TrueNAS names it after the app, something like `ix-inventory-hub-…-1`).
2. `sudo docker exec <name> cat /proc/sys/net/ipv4/ping_group_range`: `0 2147483647` means the unprivileged socket is allowed.
3. `sudo docker exec <name> python3 -c "import socket; socket.socket(socket.AF_INET, socket.SOCK_DGRAM, socket.IPPROTO_ICMP); print('ICMP datagram socket OK')"`
4. `sudo docker exec <name> python3 -c "import socket; socket.socket(socket.AF_INET, socket.SOCK_RAW, socket.IPPROTO_ICMP); print('raw ICMP socket OK')"`
5. `sudo docker inspect <name> --format 'add={{.HostConfig.CapAdd}} drop={{.HostConfig.CapDrop}} net={{.HostConfig.NetworkMode}} user={{.Config.User}}'`

If 3 or 4 prints OK, (3) can tell the two cases apart on prod. If neither does, (3) still ships and keeps today's words there; it never claims a printer is off. The same checks on dev's container (`inventory_hub`) are the build's first step for (3).

**Claude's calls (for veto):**
1. **65.1 (1), the figures.** When a review is built for an end FCC may have seen only part of (an ambiguous end, a cancel seen after lost contact, a review restart recovery opens), FCC cuts the print's file at every whole percent in the same walk as today's partial and keeps those figures on the review (a few KB). A percentage typed later is answered from them at once; a decimal is read between its two whole-percent neighbours. Why not download again: the INDX serves its files at about 15 KB/s, so job 1141's took 20 minutes.
2. **65.1 (1), the recompute.** Charge the whole print and the percentage both ask the server to rebuild the card at that basis, with the builder that made it, from the kept figures and the heads the card was built from. It charges only the spools the card already names, never a spool read from the heads now (the job-1141 rule); the builder's "#B is on XL-2 now" notes may still read them, as today. A head that used nothing by the old percentage but does by the new one gets a line of its own: with the spool the print-end read found there, else with none picked. The card gets a revision number, and an Apply from a view opened before a recompute is refused (43.2's rule for shortfall cards). The ledger then records the chosen percentage as the job's scale.
3. **65.1 (1), which cards.** The lost-contact words go on any review whose end came after lost contact (❓ or 🛑), and on one restart recovery opens ("FCC last saw it at ~30%, before FCC restarted": the NAS power cut Derek named). Charge the whole print goes on every ❓ card that has figures: the ambiguous card, and the no-spool card of an ambiguous end. The percentage box goes on those, and on a 🛑 card seen after lost contact (a cancel FCC saw late may have printed further first). A card from before the release keeps today's look.
4. **65.1 (1c), the ❓ "couldn't measure" card.** When FCC never read the print's file (`unsampled`, `replaced`), it downloads it once through the existing deferred-fetch queue, off the watcher, and then offers both controls with each head's spool to pick (FCC never read the heads for such an end). A file that can't give grams (`no_footer`, `empty_footer`, `no_download`) keeps "weigh the spool". One whose moves FCC can't read (`unreadable_moves`) offers Charge the whole print only, from its footer. **Veto this** to leave that card for the follow-on group (saves ~2–3 h).
5. **65.1 (1), times.** The card shows times in the browser's clock, from the seconds the server stores (dev's container runs on UTC, prod's on Pacific time). Activity Log lines say how long ("after 2 h 38 min"), never a clock time.
6. **65.1 (2), when to speak.** Three failed probes in a row count as lost (30 s at the monitor's busy pace, 90 s at its idle one). WARNING while a print was latched (printing, paused or at ATTENTION); INFO when the printer was idle, because switching a printer off is normal (the item asked a WARNING for both). Silent for a printer with no PrusaLink IP saved (the boot check already names those), for one that hasn't answered since FCC started, and for a one- or two-probe blip. Restart recovery, finding a latched print's printer silent, says so once.
7. **65.1 (3), how to tell.** A refused connection already proves the printer is on the network, with no ping. Otherwise one ICMP echo with a 1 s limit, the unprivileged socket first, then the raw one. FCC asks when contact is declared lost and every 5 minutes while it stays lost, and logs only a change of verdict. The Printer Status badge keeps its OFFLINE look and changes only its tooltip and accessible name, so there is no new look to show first; a separate badge label would be a picture for 59's sitting.
8. **65.1 (2) and (3), who keeps the record.** The monitor keeps each printer's contact record. The heartbeat copies the verdict into that printer's own payload (`printer_status[<name>].reach`), never as a key of `printer_status` itself (the widget reads each of those as a printer).
9. **65.1 (1), the percentage box and scans.** The box takes the field scan capture in `labels` mode (🔎 Find's), so a label scanned into it goes to the scan path. If 64.2 (11) has made the card's grams boxes `fcc-weight-box` boxes by then, the build may follow that rule instead; either way a scan never becomes a percentage.
10. **65.2, where the tag scan lives.** In a new flat module, `print_file_watch.py`, which step 2's per-printer store grows into later. It joins the escape canary's list. One WARNING per printer and word per FCC run, kept in memory (step 2 keeps it in the store).
11. **65.3, how the facts travel.** Inside `saveSpoolWeight`'s existing sixth argument, `how` (Group 54.7), posted as a top-level `weigh` beside `auto_archive`. "FCC expected" comes only from the spool's own record (an id check), never from Spoolman's error body. The wizard's two scale paths keep today's line (the scoping's step 1b; Later).
12. **65.3, a print not charged yet.** When a queued print or an open 🛑 review names the spool (FCC's own files: the fetch queue's print-end read, the review's rows), the line says so instead of comparing: "FCC expected 654.7 g, but job 1144 on INDX, which used this spool, isn't charged yet." Without this, a spool weighed while the INDX's file is still downloading (20 to 33 minutes) reads as a false drift. This is the case Group 64's Decision 1 handles at the charge; here it only changes the words. ~0.5 h, in 65.3's estimate.

## Design

### 65.1 (1): say when FCC lost sight of the print, and let the person set how far it got
**The latch.** Each good in-progress probe stamps `seen_at` (epoch seconds) beside `progress`. The first failed probe while a job is latched stamps `lost_at`, and each one counts in `misses`. A good probe clears both. The stamps ride the latch file FCC already saves every tick, so they survive a restart. `_track_print_edge`'s edge logic doesn't change; its failed-probe branch only stamps, under the lock.

**The facts on the edge.** An edge whose latch counted 3 misses or more (65.1 (2)'s rule) carries `lost_contact = {progress, seen_at, lost_at, back_at, back_state}` in its `fire` dict, on its queued fetch record (beside `end_heads`, passed only when it carries something, as `_edge_kwargs` does) and on the review record. Its heads read is labelled `back`, with the words "when FCC saw <printer> again" (a new `_HEADS_WORDS` entry), never "when the print ended". Restart recovery's reviews carry `lost_contact` too, with `why: "restart"` and FCC's start time.

**The words.**
- ❓ card: "FCC lost contact with XL at ~30% (14:02) and next saw it idle at 16:40, so the print may have gone further. If it finished, press Charge the whole print; if you saw how far it got, type that percentage."
- 🛑 card seen late: "FCC lost contact with XL at ~30% (14:02) and next saw it stopped at 16:40: it may have printed further before it was cancelled."
- Restart: "FCC last saw this print at ~30% (14:02), before FCC restarted at 16:35."
- The review's Activity Log line says the same with durations ("lost contact at ~30%, saw it again 2 h 38 min later").

**The figures, from the one download.** For an ambiguous end, a cancel seen after lost contact and a restart's review, `_compute_cancel_usage` also cuts the file at 0, 1, … 100% in the same walk, each percentage placed in the file as the printer's own is (through M73). The record keeps `figures: {footer: {position: g}, by_pct: {position: [101 values]}}`, after the same single-head fold as the usage, and the inputs its builder took (the start snapshot, the swap log and the figures at the swaps). To place the percentages without changing `fetch_cancel_gcode`'s call (34 stand-ins answer four arguments), its answer gains `"remap"` (its own `_remap`). A result without one (an old stand-in, a failed decode) keeps no figures, and that card shows no new controls, like a card from before the release.

**The controls.** On a card with figures: **Charge the whole print**, and **How far it got: [ 30 ] %** with **Work it out**, pre-filled with the last percentage FCC saw. Enter in the box works it out and never applies. Each posts `POST /api/cancel_deduct/recompute {printer_name, job_id, rev, percent | whole: true}`, which writes only FCC's pending-review file, never Spoolman:
- it rebuilds the record at that basis with the builder that made it (rows, held lines, sets, notes), from the kept figures and the heads the card was built from (Claude's call 2);
- whole means each footer head's footer grams, a head the walk can't see included;
- a head split at its swaps keeps its earlier spools' shares, and only the last spool's share moves;
- a head with grams at the new basis and no row or line before gets a line: with the spool the print-end read found there, else none picked;
- `progress` becomes the basis, `seen_progress` keeps what FCC saw, `rev` goes up, and one line is logged ("📝 XL: job 1142's review worked out again at 62% (FCC last saw ~30%)", or "… for the whole print");
- the answer is the new record, and the page redraws the card as it does after a partial Apply (`rerenderCard`).

The Apply then quotes `rev` (an older view is refused with 43.2's words), the ledger records the basis as the job's scale, the shortfall is measured against the rebuilt total, and its Activity Log line names the basis. The grams stay editable after either control.

**(1c) The "couldn't measure" card.** For `unsampled` and `replaced`, FCC queues one download of the print's file through the existing deferred-fetch queue (its own thread, its 72 h window, its claim) and adds the figures to the record when it lands. The card then offers both controls, each head's line unpicked. `unreadable_moves` offers Charge the whole print only. `no_footer`, `empty_footer` and `no_download` keep "weigh the spool".

### 65.1 (2): one line when contact is lost, one when it's back
- The monitor keeps a contact record per printer in memory (`print_monitor._CONTACT`): failed probes in a row, when the first one failed, whether "lost" was said, and the last good state and job. `_cancel_monitor_tick`'s `_probe` updates it after each probe, and the tick prunes printers no longer in the map, as it does the latch.
- `_probe_printer_state` notes why it failed beside its unchanged answer (`prusalink_api.last_probe_failure(name)`: a timeout, a refused connection, no route, an HTTP status, a body it couldn't read, no IP saved). Its return stays None for every caller (fail-open).
- Lost (3 in a row): WARNING "📡 Lost contact with XL: it was printing 'x.bgcode' (~30%) when FCC last saw it." while a job is latched; INFO "📡 Lost contact with XL (it was idle)." otherwise.
- Back (the first good probe after "lost"): INFO "📡 XL is back after 2 h 38 min (PRINTING, ~62%)." When it comes back idle with a job latched: "📡 XL is back after 2 h 38 min (IDLE): the print FCC last saw at ~30% ended while FCC couldn't see it, and its review is in 🛑 Review." The ambiguous edge's own line follows.
- Silent: no IP saved, never answered since FCC started, a one- or two-probe blip.
- Restart: `_recover_one_print_latch`'s offline branch (`cur is None`) says once, for a latched job: "📡 XL hasn't answered since FCC restarted; it was printing 'x.bgcode' (~30%) when FCC last saw it."
- Each file name through `print_deduct._esc` (print_monitor.py is already in the escape canary).

### 65.1 (3): PrusaLink stuck, or the printer off
- When (2) declares contact lost, and every 5 minutes while it stays lost, the monitor decides which:
  - a refused connection (`last_probe_failure` says refused) means the printer is on the network: no ping;
  - else one ICMP echo to the printer's IP with a 1 s limit: `socket(AF_INET, SOCK_DGRAM, IPPROTO_ICMP)` first, `SOCK_RAW` second, the standard library only (a small helper; Python 3.9);
  - if neither socket opens, FCC can't tell and keeps today's words. It never says a printer is off.
- Words, in the lost line and again only when the verdict changes: "📡 XL is on the network, but PrusaLink isn't answering. Restarting the printer brings it back, but a restart ends a print: wait until its print is done." or "📡 XL doesn't answer at all (off, or off the network)."
- The badge: the heartbeat copies the verdict into the printer's own payload (`printer_status[<name>].reach`: `"prusalink"`, `"none"` or absent), and `_stateMeta` keeps the OFFLINE look and words its tooltip and accessible name for the case.
- On dev first (its container `inventory_hub`), then the prod fact above.

### 65.2: the 2% check on finished prints, and a scan for tags FCC doesn't know
**(a) The completion check.** In the completion branch, walk the whole file inside its own try: reuse the swap walk's `whole` when there is one, else `measure_filament_usage(content, [])` (no cut, just the totals). The usage stays the footer. `_warn_parse_gap(..., completion=True)` keeps the rule (2% and 0.1 g), checks every footer head, and writes one line per print naming each head over it: "⚠️ INDX: FCC's G-code walk of 'FLEXI-~2.BGC' came to 7.50g against the slicer's 3.23g for RCOI-1 (+132.2%) and 4.63g against 1.90g for RCOI-2 (+143.7%). This finished print was charged the slicer's figures, so its charge stands, but FCC reads this file differently from the slicer: a cancelled print like it would be charged wrong." It opens with today's words, so the ⏸️ PENDING DEREK note and the tests' `_gap_lines` still match. A footer head the walk can't see is named ("a cancelled print like it would charge this head nothing").

**(b) The tag scan.** `print_file_watch.scan_tags(printer_name, filename, content)`, in a new flat module, called right after the content arrives in `_compute_cancel_usage` (before the walk's warnings, so the cause comes first), inside its own try, for every file FCC reads (cancelled, finished, ambiguous, queued).
- Known tags: PrusaSlicer 2.9.6 and 2.9.7's reserved and custom tags (TYPE:, WIPE_START, WIPE_END, HEIGHT:, WIDTH:, LAYER_CHANGE, COLOR_CHANGE, PAUSE_PRINT, CUSTOM_GCODE, the three `_GP_` placeholders, FLUSH_START, FLUSH_END, EXCLUDE_E_START, EXCLUDE_E_END) and the five markers in Derek's files (BEFORE_LAYER_CHANGE, AFTER_LAYER_CHANGE, Z:, _TOOLCHANGE_TIME<n>, _TOOLCHANGE_END), each with a one-line reason. A tag joins the list only with a test of what the walk does with it: copying the slicer's list wholesale would have marked EXCLUDE_E "known" while the walk still counted it.
- A tag's shape: ';', then capitals or underscores (a single capital only before ':'), optional digits, then the line's end, ':' or a blank. It skips Derek's template comments (";G29 P1 …", ";PET-family …", "; RETRACT AFTER TOOLCHANGE START").
- A bare word: a tag-shaped word alone on a line with no ';' (the old INDX profile's `EXCLUDE_E_START`).
- One WARNING per printer and word per FCC run (in memory). The file name and the words, which come from the file, are escaped with `html.escape(..., quote=False)` (the module can't import `print_deduct._esc` without a cycle).
- Words: "⚠️ INDX: 'RACOON~1.BGC' has EXCLUDE_E_START and EXCLUDE_E_END on lines of their own, without the ';' that makes them slicer tags, so the slicer counts the moves between them as filament used (and so does FCC). Check the printer profile's tool-change G-code." and "⚠️ INDX: 'x.bgcode' uses slicer tags FCC doesn't know: ;PURGE_START. FCC may count this printer's filament differently from the slicer."
- Cost, measured by the scoping on this PC: 0.4–0.5 s for the scan and 3–5 s for the walk on a 27–32 MB body, on the edge's or the queued download's own thread. Not measured on the NAS.

### 65.3: each weighing says what FCC expected

Quick Weigh passes `how.weigh = {source: 'quick_weigh', mode, reading, tare, tare_skipped}`; the weigh-out list's two saves pass `{source: 'weigh_out', mode, reading, tare}` (the Net save with no details sends `tare: null`). `saveSpoolWeight` posts it as a top-level `weigh` beside `auto_archive`. ## Risks
- **The review card charges real spools.** A recompute charges only the spools the card names, and the Apply stays the same write; an older view of a recomputed card is refused.
