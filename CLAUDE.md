- **⚠️ A plain `pytest tests/` run is NOT offline — it writes to real dev inventory.** This was mis-documented until 2026-08-03 and is worth internalising, because it silently shaped the whole verify cadence. The two opt-in flags guard **different services**:

It is also the leading suspect for the load-sensitive E2E flake family (a captured traceback showed `test_clone_e2e` failing because a concurrent test had moved the spool it needed — not a UI race).
- **For a fast, provably hermetic check use `--offline` (or `FCC_OFFLINE=1`)**: `"C:/Python314/python.exe" -m pytest tests/ -p no:cacheprovider -q --offline`. It skips, at collection time, every test requesting a container-touching fixture (`page`, `require_server`, `clean_buffer`, `seed_*`, `scan`, …) — so no browser ever launches and nothing can write to dev. **~20 minutes (5,897 tests on 2026-11-02; 1.5 minutes and 2,111 tests on 2026-10-14), so run it in the background.** Use it for iterating; use the full run (which includes the E2E) before committing anything that touches the frontend. Gating `require_server` alone would NOT be enough — a Playwright test can request `page` without it — hence the fixture-name list in `conftest.CONTAINER_FIXTURES`, pinned by `tests/test_offline_mode.py`.

It exists for exactly the shared-data problem above but is not yet part of the routine cadence. ⚠️ It will discard hand-made dev state, so check with Derek before using it. ## Dryer Box ↔ Toolhead Bindings (Phase 2/3)

- **Storage**: per-slot, on each Dryer Box record in `inventory-hub/locations.json` under `extra.slot_targets` — a dict keyed by slot number (string), values are Toolhead / MMU Slot / No MMU Direct Load LocationIDs, or absent = unassigned (staging/drying).
- Example:
  ```json
  { "LocationID": "PM-DB-XL-L", "Type": "Dryer Box", "Max Spools": "4",
    "extra": { "slot_targets": { "1": "XL-1", "2": "XL-2", "3": "XL-3" } } }
  ```
  Slot 4 is absent → staging only. Split boxes (one box per printer side) are first-class; the model has no `default_printer` concept.
- **Read bindings through the one guarded reader**, `locations_db.bindings_from_row(row)`: a non-dict row or `extra` degrades to `{}`, and every falsy or blank target means unbound (a stringified `false` once made auto-deploy target a location named "FALSE"). A writer that must write `extra` back guards it with `isinstance(extra, dict)` and replaces a non-dict one. A source canary in `tests/test_slot_targets_reader_migration.py` fails on the unguarded `(row.get('extra') or {}).get('slot_targets')` pattern in `logic.py`, `routes_bindings.py`, `locations_db.py` and `placement.py` (2026-10-13; `placement.py` since Group 40.1).
- **Editing UI**: Location Manager → open a Dryer Box → "🔗 Slot → Toolhead Feeds" collapsible section. Dropdowns are grouped by printer via `<optgroup>`.
- **Single-slot boxes (a PolyDryer; Group 20.2, made spool-keyed by Group 42).** A Dryer Box with `Max Spools` `1` ("0" also counts; a blank isn't managed) is lifecycle-driven: its slot `1` binding records the head ITS OWN spool is loaded on, not a feed. It attaches when that spool deploys from it, follows the spool head to head (Derek's Q-A; only from the head it is attached to, never taking it off another head: `attach_single_slot_box_to_toolhead(..., steal=False)`), and lets go only when that spool leaves the head by any path, keyed on the leaving spool's trail through `locations_db.detach_single_slot_box`: eject, Return, any move and force-unassign (`logic._release_single_slot_box`), a wizard or `/api/spool/update` location edit (`logic.release_box_after_direct_write`), and the archive edge of a print to 0 g (`spoolman_api._release_box_on_archive`, also after a PATCH that landed but timed out). Undo re-attaches only the box the undone move released (the record's `released` / `ejection_released`). Ejecting a different spool from the head no longer unbinds it. It never auto-deploys, is never a stranger's 13.6 home, and Return's fallback never sends a stranger into it. Its spool is in slot `1` (`locations_db.effective_slot`: a blank slot reads as "1" for the box's sole occupant only); a second spool put in while another claims slot 1 (its own spool, deployed) goes in unslotted, and `/api/quickswap` refuses a slot two spools claim (`quickswap_ambiguous_slot`) and, given the card's `expected_spool`, a slot holding another spool now (`quickswap_spool_mismatch`, Group 51.5). A spool entering it from a non-head place records `fcc_pre_box_location` ("Pre-Box Location (system)"), so ejecting it out of the box puts it back there. Since Swap option C the same note also records where a spool sat before a multi-slot box's slot (`logic._note_after_move`: "LR-MDB-2:1>CR-CT-2-R1" is that slot, then the plain place behind it; onto a head from a plain place, that place; a deploy, a Return to its own slot, head to head and a re-scan keep it), and a PolyDryer's spool whose noted slot is taken goes to that plain place, not into the box with no slot. The toolhead's Quick-Swap grid labels it "🔗 attached — follows #50", or a stale attachment with Unbind (read strictly, so a Spoolman blip says "couldn't read" instead; the Unbind PUT names the head it showed as `expected_target` and is refused with `binding_moved` if the box has moved since). **For a new single-spool dryer, use Type `Dryer Box` with `Max Spools` `1`**; nothing keys on the `PM` prefix.
- **Quick-Swap**: Location Manager → open a toolhead (Tool Head / MMU Slot / No MMU Direct Load) → "⚡ Quick-Swap Slots" grid aggregates every (box, slot) feeding that toolhead. Tap or keyboard-nav + Enter to swap. `Q` focuses the grid; arrow keys move; Enter triggers confirm overlay (inline div, never nested Swal).
- **Keyboard shortcut reference**: `?` button in the dashboard title bar (or the `?` key anywhere outside inputs). Any new shortcut added elsewhere should call `window.registerShortcut({id, scope, keys, description})` in `static/js/modules/shortcuts_registry.js` so the overlay stays complete. The same window is the in-app help (Group 55.3, "In-app help" under Project Conventions): in a dialog with help, `?` opens that dialog's help first.
- **Indxx forward-compat**: the model scales to an arbitrary number of toolheads by simply adding entries to `config.json:printer_map`. No schema change required for the planned Core One+ → indxx upgrade (8–10 toolheads).
- **Legacy**: the old `config.json:feeder_map` key was retired in M7. A back-compat migration in `startup_migrations.py` (called from `app.py` at import) imports a surviving install's entries into `slot_targets` on boot, but is **skipped while any Dryer Box carries a `slot_targets` key** (even `{}`; `locations_db.dryer_bindings_are_authoritative`, Group 46.4). Before that, a box whose slots were all cleared in Feeds (saved as `{}`) was silently re-bound from the stale seed on the next restart. It is a live predicate, not a latch: re-typing the only keyed box away from Dryer Box, or deleting it, re-arms the import. Harmless while dev's and prod's `feeder_map` are empty; deleting the import is the durable fix (Derek's call). Same shape as the `printer_map` seed retirement (hotfix 2026-09-29).

## Project Conventions

- **Inline overlays MUST route through `window.mountOverlay()`** (Group 15 — see [docs/agent_docs/tasks/15-canonical-overlay-mount.md](docs/agent_docs/tasks/15-canonical-overlay-mount.md) for the rationale). Don't `createElement` + `document.body.appendChild` + custom `focusin`/`keydown` listeners; the helper owns the z-index ladder, the focus-guard that defeats Bootstrap's `_enforceFocus`, host-close cleanup, occlusion of underlying selects, and idempotent teardown. Reference implementations: [weight_entry.js](inventory-hub/static/js/modules/weight_entry.js), [weight_utils.js](inventory-hub/static/js/modules/weight_utils.js) (missing-tare prompt), [duplicate_picker.js](inventory-hub/static/js/modules/duplicate_picker.js), [inv_quickswap.js](inventory-hub/static/js/modules/inv_quickswap.js) (Quick-Swap confirm), [inv_details.js](inventory-hub/static/js/modules/inv_details.js) (force-location escape-confirm).
  - **Z-index ladder** (constants on `window.OVERLAY_Z`):
    - `STANDARD = 20000` — single overlay above any Bootstrap modal/offcanvas. Pass `tier: 'standard'` (default).
    - `CONFIRM = 20100` — confirm overlay above a standard overlay (e.g. missing-tare prompted from inside WeightEntry). Pass `tier: 'confirm'`.
    - Toast layer is 11000 — intentionally BELOW overlays so a confirm isn't drowned out by toast noise.
    - The ⌨️ shortcut list sits above both: backdrop 20200, list 20201 (dashboard.html; Group 58 review). It is read over whatever is open, and what is under it holds its keys while it is up (the audit panel's N and arrows, `personMayPress`), so behind an overlay it left those keys dead with no sign why. Its capture-phase Escape runs before `mountOverlay`'s: Escape closes only it. Its capture-phase handler also stops a person's Enter, because a dialog's own Enter handler doesn't ask `personMayPress`, and with the list on top that answered a question nobody could see; a scan's Enter goes on (`enterIsAScan`), and scans work under it. While it is up the toast layer is drawn over it (`body.fcc-shortcuts-up #toast-container`, 20300; the class is `toggleShortcutsOverlay`'s, Group 58 re-review), so a scan's outcome is still read there, a failed one's 7 s toast included; everywhere else toasts stay under the overlays. Closing it gives the keyboard back to what had it when it opened, when the close left the focus nowhere (the page, after a click on its backdrop, or its own ✕): Done's question, whose keys sit on its own overlay, heard nothing after a click there, and its Enter was dead.
  - **Focus guard** is the working pattern from `89c6f39`: capture-phase `focusin` listener on `document` that `stopImmediatePropagation`s events targeting the overlay subtree. Mounting INSIDE the modal subtree to escape `_enforceFocus` was tried and reverted (13.1) — it loses the z-index war. Do NOT subtree-mount overlays.
  - **Escape contract**: `mountOverlay`'s `onEscape` (or default cleanup) uses `stopImmediatePropagation`, so sibling capture-phase listeners on `document` won't fire. Only the overlay on top answers it (the highest tier, then the last mounted), and an overlay's own key handler acts only while `window.isTopOverlay(el)` says it is on top (Group 57 review, round 6: the Quick-Weigh answered the missing-tare prompt's Escape and Enter). Callers must NOT also handle Escape — pass `onEscape: () => yourCancel()` if you need a custom cancel side-effect.
  - **Host cascade**: pass `host: someBootstrapModalEl` to auto-clean the overlay when the host emits `hidden.bs.modal` / `hidden.bs.offcanvas`. No overlay outlives its parent.
  - **Tab**: pass `trapTab: true` (default false) on a window a person can Tab out of. While it is on top (`isTopOverlay`), Tab and Shift+Tab wrap inside its focusable, visible, enabled controls, read at the press, and a focus outside it comes to its first one. It stops only Tab, with `stopPropagation`, so the document's other capture listeners still hear it (the legacy picker reads a Tab as a person's key). The audit panel, the 🧺 list, 🔎 Find a spool, the audit's report window and the legacy picker pass it (Group 58 review: Tab walked out of the list onto the panel's Cancel Audit, and Space pressed it). A list with roving `.kb-active` rows keeps the active row in the tab order (`tabIndex = 0`) or Tab can't come back to it.
  - **The global search's keys stand down under an overlay**: fab_drag.js's `/` and Ctrl/Cmd+K open the search (a Bootstrap offcanvas, z 1045) only while no `mountOverlay` is mounted and the ⌨️ list is down. Under one it opened behind it and its box took the keyboard 400 ms later, so the next scan was typed into a box nobody could see (the audit's 🧺 list, Done's question, the legacy picker, Find under the ⌨️ list). A person's `/` is still taken there, out of the scan buffer too (or it would start the next scan); a scan's `/` and one typed in a field go on. Pinned by `tests/test_global_search_key_covered_js.py` and the `/` cases in `tests/test_audit_find_and_tiles_58_e2e.py`.
  - **No nested `Swal.fire()`** — the original prohibition stands. Nested Swals don't stack and dismiss each other; route confirmation dialogs through `mountOverlay` instead.
  - **Z-order incident symptom checklist** — each symptom maps to a `mountOverlay` behavior; if you see one, suspect a bypassed `mountOverlay`:
    - Click triggered something but I can't see it → mount target wrong (must be `document.body`).
    - Overlay rendered behind sibling modal chrome → wrong tier or subtree-mounted.
    - Brief processing flash then "nothing" → overlay closed itself but parent listener didn't know.
    - Inline overlay's Escape closes BOTH the overlay and its host modal → caller is also handling Escape; let `mountOverlay` own it.
    - Overlay lingers after host modal closes → didn't pass `host`.
    - `<select>` dropdown under the host intercepts overlay clicks → didn't pass `occlude`.
- **Bootstrap gating dialogs (`#confirmModal` / `#safetyModal` / `#actionModal`) — never `.show()` / `.hide()` them directly (2026-09-12).** Go through `requestConfirmation` / `promptSafety` / `promptAction` / `closeModal` (`inv_core.js`). Bootstrap 5.3 silently IGNORES `show()` while a modal is fading out and `hide()` while it is fading in; FCC re-prompts from inside a dialog's own callback (eject → active-print re-confirm → "true unassign"), so a direct call drops the prompt with no error and leaves its callback armed. The helpers track each dialog's phase from Bootstrap's public events and queue the one call Bootstrap would drop. ## Spool / Filament write surfaces

Every code path that calls `spoolman_api.update_spool` or `update_filament` has the same two failure modes: (1) up to Spoolman 0.25 a filament's and a vendor's PATCH REPLACED the whole `extra` dict (a spool's has merged key by key since 0.22, every entity's since 0.26; dev and prod run 0.27.0), so a partial payload silently wiped siblings; the read-merge stays as that guard; (2) on rejection both functions return `None` and most callers don't surface the actual error body. Both are the root of the 2026-04-26 / 2026-04-27 prod outages.

Conventions every write surface MUST follow:

- **Use the helper, not inline diff loops.** `spoolman_api.compute_dirty_extras(existing, requested, system_managed=...)` returns `(dirty_dict, stripped_keys)`. Pass `system_managed=spoolman_api.SYSTEM_MANAGED_EXTRAS` whenever the surface is user-driven editing (wizard, vendor edit modal, manufacturer edit modal, etc.) — that frozenset enumerates the keys owned exclusively by `perform_smart_move` / `perform_smart_eject` (`container_slot`, `physical_source`, `physical_source_slot`) and FCC's own breadcrumbs (`fcc_pre_archive_location`, `fcc_pre_audit_location`, `fcc_pre_box_location`). Every Undo and Smart Load snapshot writes them all, and Spoolman rejects a whole PATCH carrying an unregistered extra, so a new one goes into `REQUIRED_SPOOL_EXTRAS` (startup registers it) and `setup_fields.py` in the same commit.
- **Surface `LAST_SPOOLMAN_ERROR` on failure.** Both `update_spool` and `update_filament` populate the module-global on every rejection (the symmetry was fixed 2026-04-27 — pre-fix, only `update_filament` did), and so do `create_spool` and `create_filament` since Group 53.2 (before, `/api/create_filament` answered an earlier write's refusal as its own); each clears it on success. Read it in your `else:` branch and either (a) write to the activity log via `state.add_log_entry(..., "ERROR", "ff4444")`, or (b) return it in the JSON response so the frontend can `showToast(err, "error", 7000)`. ## Multi-agent Workflow budget

**Before launching a multi-agent `Workflow`:** state the agent count + rough cost
first. **Batch the verify stage** — never one agent per finding (that is what blew
a usage window on 2026-08-02: 55 findings → 55 verifiers; re-running the same
review at 14 findings/agent cost 710K tokens instead of 4.4M, with zero agent
errors and *more* usable signal). If the fan-out is large and the current usage
window is unknown, ask for quota / reset time / work-headroom before starting.

This subscription is shared with Derek's **paid work** (a separate machine and
workspace — everything in this repo is a hobby project), so an oversized burst
here can block real work. Quality is NOT the thing to cut: keep the effort and
the rigor, shape the fan-out better and defer optional depth to an idle window.
Night/scheduled work must never sit on the critical path, and scheduled agents
start with zero context so they need self-contained instructions. Pay-as-you-go
credits exist but are a **last resort** — propose and discuss, never assume.

## Working Groups (Batched Tasks)

Tasks from `Feature-Buglist.md` are organized into batched working groups for efficient execution. Each group bundles related items that share code surfaces.

- **Index:** `docs/agent_docs/working-groups.md` — status table, recommended order, usage instructions.
- **Task files:** `docs/agent_docs/tasks/01-*.md` through `11-*.md` — self-contained specs per group.
- **Commands:** `/project:work-group <N>` to start a group, `/project:finish-group` to wrap up, `/project:refresh-groups` to re-analyze the buglist after adding new items.
- **Reviews work from `docs/agent_docs/review-checklist.md`** (2026-11-03): the lenses that found real bugs in Groups 50, 57, 58 and 61, so a review from a new chat starts with them. They are: a scanner is a keyboard; a double click's second press; stacked overlays; real runs and old-code proofs; honest reads and writes; ordering and staleness; spools and places; what a person reads. Add a lens there when a review finds a new class of bug.
- **Branches: delete at merge (Derek, 2026-10-29).** Whatever merges a branch into `dev` (a group, a bundle, a fix, a hotfix's forward-merge, a sub-branch into its group's branch) deletes it in the same step, here and on GitHub, where it was pushed as a backup: `git push origin dev` first, then `git branch -d <name>` and `git push origin --delete <name>`, each name written out in the command (auto mode refuses a delete whose names it can't see, such as names read from a file). Nothing else is recorded: the merge keeps the branch's commits (`git branch <name> <sha>` brings one back). A branch kept unmerged gets one line under "Branches kept" in `docs/agent_docs/working-groups.md` (why, and until when), and the commit that takes the line out says why it went. `/project:work-group` starts by deleting any work branch that `git branch --merged dev` or `git branch -r --merged origin/dev` still lists. Derek: *"We should probably try and stay more on top of cleaning up git and local when we are done with a branch. So we don't end up spending large amount of time and tokens researching if anything is unresolved"* (35 merged branches had piled up by 2026-10-29, and checking them took two agents).
