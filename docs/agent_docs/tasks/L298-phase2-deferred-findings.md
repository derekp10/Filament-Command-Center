## [MEDIUM] Cancel racing an in-flight commit reports "nothing moved" while the move proceeds

**Still live because:** Fix #4 only serialized commit-vs-commit. `logic._BULK_MOVE_COMMIT_LOCK` (logic.py:1142) is acquired and released solely inside commit_bulk_move_session (logic.py:1153, 1183-1184); NEITHER cancel path consults it:

Meanwhile the in-flight commit captured `source, dest` into locals at logic.py:1157 before calling plan_bulk_move/execute_bulk_move, so wiping the session dict has zero effect on it: perform_smart_move keeps writing every spool (logic.py:908) and the aggregate SUCCESS log line still fires (logic.py:955-957). The finding's mirror case (CMD:DONE racing the panel Commit) IS now fixed by the lock.

**Suggested fix:** Either serialize cancel behind the same lock (acquire non-blocking in both cancel paths; on failure return `{'success':False,'msg':'A bulk-move commit is in progress — it can no longer be cancelled.'}`), or stamp the session with a monotonically increasing epoch at start, capture it in commit before perform_smart_move, and have cancel refuse (with a loud WARNING log) while a commit generation is in flight.
