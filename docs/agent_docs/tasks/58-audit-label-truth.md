## Derek's steer of 2026-11-01 (read this first; it overrides the study where they differ)

Derek's backstory: Audit predates labelled rows. It was an earlier AI's idea, meant for big places (the dining room cart, the small carts before they had rows), never for a 4-slot dryer box: scan a place, scan what is there, then do something about what was listed and not scanned. It may need a redesign, or a decision on whether to keep it (**not decided yet: keep or retire is his call, asked 2026-11-01**).

**His rule:** a spool has one location. If its own record says it is somewhere known (a toolhead, a dryer box), it stays there: an audit of another place doesn't touch it, and shouldn't count it as being in that place.

**What that means in the code:** the audit's list comes from `get_spools_at_location`, the same reader that draws a place's contents, and that reader also returns spools with only a trail there (deployed from a box) and, for a Room or a Printer, every spool under its first segment. So the fix is one rule at the location scan: **expected = spools whose own `location` is exactly this place**. It replaces the study's "left where they are" list, the "on XL-4" tile and the separate count: those spools are simply not on the list. Done's re-read before any write stays (a spool can move during an audit).

Today's Done on CR parks the other 79. DR-CT-1, the biggest single place, has 19 filed directly; every other place has 9 or fewer. 0 spools are parked at UNKNOWN on dev and 0 carry `fcc_pre_audit_location`; nothing reads that note (the "recovery scan" its comment promises was never built). Prod not read.
- **The wrinkle (Claude's call):** a spool loaded from a bound dryer box physically sits in that box, feeding the head. So a scanned spool that isn't on the list but whose trail names this place is a quiet "found, loaded on XL-4 from here", not an Extra. A scanned spool filed anywhere else is an Extra, and says where FCC has it.
- **His forgotten-spool case stays on the list:** a spool auto-returned to a place on record and physically put somewhere else is filed here and isn't here. That is the audit's real job, and the rule keeps it.

### 2. The location scan (the one rule)
Order: a second location scan refuses with its words; `UNKNOWN` / `UNASSIGNED` refuse ("… is a list, not a place you can audit"), WARNING, no read; then one strict read of the whole non-archived list (`get_all_spools_strict`, the only read here, in try/except). On failure store nothing, WARNING, msg "Couldn't read X from Spoolman, so the audit hasn't started. Scan it again in a moment."
**Expected = spools whose own `location`, upper-cased, equals the place.** Build rows through `spoolman_api._build_location_match` (never a copy of it); keep only `not is_ghost and location.upper() == place`. Everything else the old list held (a trail here, or a prefix hit under a Room or Printer) is not expected. If nothing is expected and locations.json has no such row: refuse "X isn't a place FCC knows", store nothing. A place with spools but no row still audits. A locations file that can't be read refuses too, store nothing: "Couldn't read the locations file, so nothing was recorded. Scan it again in a moment."
`start_note`: when spools sit in places inside this one (count by `locations_db.is_descendant`, on the same list, never through the matcher, whose test forbids it): "7 are filed here. 79 more are in the places inside it, and this audit doesn't check those: audit each of them." (with nothing filed here: "Nothing is filed here itself. …"). A Printer row reads the same, naming its heads as places. Shown in the log line and on the panel.
Stored row: `{id, display, color, color_direction, remaining_weight, slot, location}` from the match; `/api/audit_session` draws from `rows` with no Spoolman read, falling back to `_enrich` for a row with no stored data (keeps the endpoint tests). It also answers `audit_id`, `note` (the start note), `trail` rows, `stats.trail`, and each row's `where`.

### 3. A spool scan
No place yet: refuse with `msg`. A spool already scanned answers quietly, as now, with no read, except a row recorded while Spoolman wasn't answering (below). An expected spool is found; "(N left)" counts the expected spools not yet scanned, never subtracting extras.
Not expected: read first, through `get_spool_answer`, BEFORE recording. No answer: record it as an extra with "couldn't read where FCC has it" (200, never a 500). A row recorded that way is the one row a re-scan reads again, so a blip can't leave a loaded spool an Extra for good, or a mistyped id on the report: only once the read has answered is the row taken out of `scanned_items` and `rogue_items` and replaced by what the read says, a trail row or an Extra with its real place; a 404 leaves no mark (its row, `found_by`, `label_flagged` and `last_found` go too); while Spoolman still won't answer the row stays as it is, the scan still selects it, and nothing more is logged. An answer with no `id` (a truthy 404 body): refuse "Spool #N not found", record nothing. **Its own location is a toolhead (or a Printer row that is its own head) and its `physical_source` names this place: `trail_items`, a quiet "found: loaded on XL-4 from here"** (a spool loaded from a bound box physically sits in that box). Only locations.json can say it is on a head, so a file that can't be read refuses with section 2's words and records nothing: the person scans it again. Anything else: `rogue_items`, stored row carrying where FCC has it (a blank location reads Unassigned), WARNING line. Log and panel say **Extra**, not "rogue"; the session key stays. A spool at `UNKNOWN` says so: section 8.

### 5. Done
`process_audit_scan` with `done` writes nothing except when nothing needs parking. `logic.plan_audit_done(session)` reads strictly with archived included (`get_all_spools_strict(allow_archived=True)`), so a missing id is a deleted spool, and answers `{read_ok, read_error, occupants, park: [{id, display, where, slot}], stays: [{id, display, where, why}]}`; `occupants` counts the place's spools as a read of it lists them (a spool loaded from it included, an archived one not, as `box_slot_claims` goes by), for the slot the record keeps. For each expected, unscanned id: deleted → stays ("no longer in Spoolman"); archived → stays; its location is no longer exactly the place → stays, `where` = where it is now; in `state.GLOBAL_BUFFER` → stays; a head or one-spool printer (`_holds_one_spool`, so a head audit parks nothing) → stays; else park. Extract Bulk Move's skip tests (logic.py:3502-3548) into one helper used by both, its words and Bulk Move's behaviour unchanged.
A failed read: nothing written, audit stays open, WARNING, `{status: error, msg: "Couldn't read X from Spoolman, so nothing was moved. Try Done again in a moment."}`. `park` empty: the report, then `_end_audit('done')`. Else `{status: 'ask', audit_id, location, park, stays, found, expected}`.
The route: on `ask` answers `{"type":"audit_done_question", …}` when the request carries `audit_ask: true` (processScan sends it on every scan), else `{"type":"error","stale_page":true,"msg":"This page is out of date, so Done did nothing. Reload the page (Ctrl+F5) and press Done again."}` with a WARNING. Every answer that ended the audit carries `audit_ended: {id, why}`.
`POST /api/audit/park` `{audit_id, ids, today}` → `logic.park_audit_missing(audit_id, ids, today=None)`: takes the end lock (a loser: `{success: false, busy: true, msg: "The audit is already finishing."}`); a different or ended audit: `{success: false, stale: true, msg}`, nothing written; re-plans; parks only `plan.park ∩ ids`; for each, `get_spool_answer` right before the write and any change to a stay, never a write. The write is `_move_write(sid, 'UNKNOWN', new_extra)`: `fcc_pre_audit_location` = section 8's note, `container_slot`, `physical_source`, `physical_source_slot` and `fcc_pre_box_location` set to `""` (a popped key is kept by the merge). A comment says why this isn't `perform_smart_move` (it would take a spool off an idle head in a race). Failed writes: ERROR line with `LAST_SPOOLMAN_ERROR`, listed. Landed writes only go in one undo record, `_push_undo({target:'UNKNOWN', moves, extras, labels, released:{}, ejections:{}, ejection_extras:{}, ejection_released:{}, displaced:{}, summary, origin:'audit', only_if_at:'UNKNOWN', slots, place_had_row})`; `moves` holds the spool's real place, `extras` every `SYSTEM_MANAGED_EXTRAS` key as it was, `slots` each spool's effective slot from the plan's `occupants` (the place as it was before any write, so a sole occupant's blank reads "1" and a second spool's stays blank), `place_had_row` whether the place had a locations.json row. The audit ends in the same request on a partial failure (Undo is refused while one runs, and there is a record to protect). A Yes where every write failed and none landed has no record to protect: no report and no end, `{success: false, parked: [], stayed, failed, msg}` with no `audit_ended`, `msg` saying nothing was parked, which spools couldn't be, and that the audit is still open so Done can be pressed again (its scans are the whole point, as for a failed read). A Yes that found nothing left to park and failed nothing still ends the audit. Otherwise the answer is `{success, parked, stayed, failed, msg, audit_ended}`. `success` only when nothing failed.

### 6. Undo (audit records only; ordinary Undo's behaviour and tests don't change)
For a record with `only_if_at`, each spool is sorted the same way for the question (`_undo_guard`) and right before its write (`_undo_guard_kind`): a deleted spool (answered, no `id`; a 5xx isn't that, `get_spool_answer` reads it as `(None, True)`, unreadable) is dropped, never blocking; a spool not at `only_if_at`, or archived wherever it is, is left alone, named with where it is (an archived one says so, "#1 at Unknown (archived)": the list read that checks a slot can't see it), and counts as neither restored nor failed; a spool whose place had a row at the park (`place_had_row`) and has none now stays at Unknown with its note, counts as neither, and the question and the answer say so once ("LR-MDB-1 is gone from Locations, so #1 and #2 stay at Unknown."; a list with no rows at all is one that couldn't be read, never a place gone; `left_alone` lists such a spool too, which gives the page's toast its 7 s); a spool whose recorded slot (`slots`) another spool claims now (one strict read per box; `box_slot_claims`, as the displaced path) stays at Unknown, counted failed, ERROR line.
A failure that says nothing about the spool leaves Undo available.
