## Today's code (anchors, `dev` @ `3388c7d`)

### 66.1 — the vendor edit
- **The events:** `vendorEditSave` (`inv_details.js:3629-3723`) POSTs a create or PATCHes an edit, then dispatches `vendor:created` (`:3699`) or `vendor:updated` (`:3706`) with `{id, vendor}`, the vendor as Spoolman answered it.
- **Edit Filament's listener** (`inv_details.js:3725-3755`) renames `#fil-detail-vendor` and Edit Filament's name box, then fires `input`. Its comment says it refetches `/api/vendors`; it doesn't. Edit Filament has no `vendor:created` listener at all.

## Design

### Rules to keep (CLAUDE.md, the wizard's write surfaces)
- A clear goes out only for a box the person changed: `wizardState.touchedExtras` and `touchedNative`, reset by `wizardReset`. A value set by code is never a touch (54.5; the 2026-10-21 review).
- An extra clears with the delete sentinel (`window.FCC_DELETE_EXTRA`), in edit mode, for a touched key only; a plain number box clears as `null` (54.5).
- The inherited marks: Edit Spool never saves a price or empty weight the spool only inherits as its own (54.8); New Spool's and Clone's boxes follow a filament picked afterwards (R2-1 / R2-3); in Edit Spool the filament box never writes over the spool's own (S1); "↩ from filament / vendor" shows exactly while the value is inherited (L1); new spools and clones save the cascade's empty weight as their own (L34).
- A key a number box can't take is no edit (R2-2).

### Build order
66.6 (offline, alone) → 66.3 → 66.2 → 66.4 (after 66.2: with the capture, a Prusament link typed into Comment reaches the scan path, and 66.2's guard must be there to meet it) → 66.1 with 66.7's behaviour (both change the empty-weight component and the same listeners) → 66.5 → 66.7's mark after D2. One commit per member, red-first tests.

### 66.1
- **Edit Filament keeps its vendor by id.** `refreshVendorBadge` checks the id it holds first: while the box's text is that vendor's current name, the id stays. A name is looked up only for what the person typed; a name two vendors share takes the lowest id, as today.
- **On `vendor:updated` and `vendor:created`,** Edit Filament replaces the cache entry from `e.detail.vendor` at once, then re-reads `/api/vendors`. For the window's own vendor it redraws the name, the pill, the hint, the placeholder and Use Vendor. `bindEmptyWeightField` gains `setVendor(v)`: it updates Use Vendor's record, and changes the box only while it shows the vendor's value untouched (66.7); a typed value, or one set with Use Vendor, stays.
- **The wizard,** on the same events: redraw the visible vendor name (`wizardComboboxSet` with the id and the new name); re-resolve the filament box while it shows the vendor's value untouched (66.7) and the spool box while it shows "↩ from vendor" untouched (`wizardSetSpoolEmptyWeightInherited`). `_wizardCascadeVendorEmptyWeight` keeps filling an empty box, as before. Edit Spool's prefill picks the vendor by the filament's own id (`f.vendor.id`), and by name only when the list doesn't hold that id.

- **The post-archive prompt's** vendor write dispatches `vendor:updated` with the answer's vendor.
- **The server:** a strict vendor-list read (a failed read raises, never `[]`), used by a name check in `api_create_vendor`, and in `api_update_vendor` when the payload's `name` differs from the vendor's own.
