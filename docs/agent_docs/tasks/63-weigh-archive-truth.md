## Design

**Build order:** Derek's two answers (if not asked yet) → 63.3 → 63.1 (the archive helper) → 63.4 with 63.2 → 63.5 → 63.6 → 63.7 and 63.9 → 63.8 last (after 62.4's `trapTab` and 63.9(b)'s box change are in) → a review from `docs/agent_docs/review-checklist.md`, its fixes, the full run, the pictures, Derek's OK.

### 63.1
- One helper writes an archive's outcome (e.g. `spoolman_api._archive_outcome(existing)`): location blank; slot and trail blank; `fcc_pre_box_location` blank when set (63.4); and `fcc_pre_archive_location` set to the place by Derek's rule, or written empty when there is none (a spool at Unassigned, at Unknown, or on a toolhead under (b)). The weigh edge, `_take_archived_off` (which keeps writing no place: the person asked for the spool somewhere else) and 63.2's take-off all use it.
- (a): `_known_room_of` moves into `locations_db` (logic calls it there), and the room note is a place or a record by Derek's sub-answer. (b): one condition (a printer-map head, a toolhead-type row, or a Printer row that is its own head gets no place). Old toolhead notes are read by the same rule at the refill; no data is rewritten.
- The refill restores the noted place only while the spool is Unassigned; otherwise the spool stays and the note is used up. A note "UNKNOWN" reads as none.
- In `update_spool`, any write that takes a spool out of the archive writes `fcc_pre_archive_location: ''`, unless the caller sent it. `perform_undo` doesn't write back `fcc_pre_archive_location` for a spool it leaves in stock.

### 63.2
- **The take-off, in the route.** When `/api/spool/update`'s write archived a spool (not archived before) that is still at a place, the route takes it off in the same request with 63.1's helper, working from the record Spoolman just answered (no extra read), and releases its single-slot box. It asks nothing about a print, as the archive edge never has (a spool weighed empty is in the person's hand; the page's request sends `confirm_active_print: true` today for the same reason). `location_now` says where it ended; a new `still_at` names the place when the take-off failed, so the page's warning words stay. The page stops posting `force_unassign` after a save.
- **(a) the retry.** A take-off that fails goes into a small store (e.g. `data/pending_archive_takeoffs.json`, a flat module beside `cancel_fetch_store.py`, reading `FCC_DATA_DIR` once at import as the four stores do). The print monitor's loop retries due entries: first after ~30 s, then backing off. Each try re-reads the spool strictly (`get_spool_answer` plus its id): a spool refilled, moved or deleted since is dropped with an INFO line; otherwise the helper's write, and when it lands one INFO line and the entry goes.
- **(b) the list.** After 5 failed tries (or at once, under (b) alone), one WARNING Activity Log line names the spool and its place, with a "Take it off" button (a delegated click, the 🛑 review line's pattern) that runs the same take-off through a small new route. The line comes back at every restart while the entry waits (`startup_migrations`, as for cancel reviews).
- **The protection, either way.** `_auto_unarchive_on_refill` treats a spool still archived at a place as if its note named that place, its slot included. `_unarchive_destination` checks every one-spool place (a printer-map head, a toolhead or Printer row, a single-slot dryer box, a row whose Max Spools is 1) and a multi-slot box's slot (another spool claiming it, by the one slot rule). Taken, or unreadable: Unassigned, slot and trail cleared, the 42.3c warning. The one-spool tests it needs move into `locations_db`.
